# Evidence Update — Chapter 25: Dari Keputusan ke Eksekusi

## Evidence focus

Chapter 25 addresses the gap between deciding and producing results. A decision becomes operational only when ownership, resources, sequencing, coordination, feedback, and adaptation are established.

### 1. Implementation is a distinct managerial problem

A sound choice can fail during execution because responsibilities, resources, incentives, coordination, capabilities, or assumptions are misaligned. Therefore “we decided” is not equivalent to “the organization can execute.”

### 2. Goals need implementation mechanisms

Research on implementation intentions shows that specifying when, where, and how an intended behavior will occur can improve goal enactment. The book should use this as evidence for converting vague intention into concrete action, not as a guarantee of organizational execution.

### 3. Implementation benefits from feedback and monitoring

Execution requires observing whether actions produce the intended intermediate results. Monitoring is not only for reporting; it provides information for adjustment.

### 4. Ownership must be specific

“Team X will handle it” may be insufficient. Execution often requires clarity on:
- accountable owner;
- supporting roles;
- deliverable;
- deadline;
- dependencies;
- decision rights;
- and escalation path.

### 5. Coordination is part of execution

Many execution failures occur at handoffs rather than within a single task. Dependencies should therefore be made visible.

### 6. Plans should be adaptive without becoming optional

A plan can change when assumptions or conditions change. Adaptation should be evidence-based and explicit rather than becoming an excuse for missed commitments.

## Editorial implications

- Convert decision into observable actions.
- Assign one clear accountable owner for major outcomes.
- Identify dependencies and bottlenecks.
- Define minimum viable execution and checkpoints.
- Monitor leading indicators where possible, not only final outcomes.
- Establish escalation triggers.
- Protect execution from unnecessary priority churn.
- Distinguish legitimate adaptation from silent abandonment.
- Preserve decision rationale so later changes can be understood.
- Do not confuse activity volume with progress.

## Proposed book synthesis

**Decision → Owner → Outcome → Plan → Dependencies → Execute → Monitor → Adjust → Escalate/Continue**

This is a book working model, not a validated execution taxonomy.
